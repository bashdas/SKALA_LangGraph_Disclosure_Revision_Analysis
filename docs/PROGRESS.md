# 진행 기록

## 0단계 — 완료 (2026-09-15)

### 구현

- 충돌 방지를 위해 `disclosure-impact-agent/`에 독립 Python 3.11+ 프로젝트를 구성했다.
- 안전한 오프라인 기본 설정(`fixture` + `fake`), FastAPI `/health`, 한국어 Streamlit 시작 화면을 구현했다.
- 직접 의존성 고정 파일, `.env.example`, 실행 README와 설정/헬스 테스트를 추가했다.
- 가상 A사의 계약금액 120억원→90억원, 종료일 2026-12-31→2027-03-31, 최근 매출액 800억원 사례를 synthetic HTML 원문·메모·기대 JSON으로 준비했다.
- 데이터 모델, 상태 전이, 1~6단계 계획과 데이터 접근 조사 결과를 문서화했다.

### 실제 검증

- OpenDART 공식 공시검색/원본파일 가이드의 요청·응답 규격을 확인했다.
- 현재 DART API 키가 없어 실제 API를 호출하지 않았다.
- 공개 검색에서 정정 공시 제목 후보 1건만 확인했으며 원문 쌍은 확보하지 못했다.
- Python 3.14.6 환경에서 `PYTHONPATH=src .venv/bin/pytest`를 실행해 3개 테스트가 통과했다(0 실패, 2개 의존성 deprecation 경고).
- 모듈 compileall과 두 JSON fixture 구문 검증이 통과했다.
- Uvicorn을 실제 기동하고 `GET /health`가 HTTP 200과 `fixture`/`fake` 상태 JSON을 반환함을 확인했다.
- Streamlit을 실제 기동하고 `/`와 `/_stcore/health`가 각각 HTTP 200을 반환함을 확인했다. 브라우저 시각 QA는 수행하지 않았다.

### 미해결

- 실제 정정쌍 3건 목록/원문/정정표/계약 관계 검증.
- 실제 양식군 확정, 원문 업로드와 파서, LangGraph, LLM 분석, 승인/저장.
- 합성 fixture 결과는 실제 API 또는 실제 LLM 성공으로 보지 않는다.

### 다음 단계 준비

원문 형태 합성 fixture와 기대 변화가 준비되어 1단계 오프라인 파서 개발을 시작할 수 있다. 실제 양식 일반화는 DART 키 또는 사용자가 제공한 실제 원문 없이는 준비되지 않았다.

## 1단계 — 완료 (2026-09-15)

### 구현

- 문서/증거/필드/정정 항목/추출 문제/관계 후보/변경/비율/연쇄 비교 스키마를 분리했다.
- synthetic HTML의 계약 본문·정정표·각주를 직접 파싱하고 SHA-256, 표/행/셀 및 문단 위치, 원문 문자열을 보존한다.
- 금액 단위, KRW/USD, 날짜, 비율과 최근 매출액의 연도·연결/별도, 부가세·확정/조건부 기준을 정규화한다. 미공개·유보·빈 값·0·파싱 실패를 구분한다.
- 정정표 전/후와 기준/정정 본문 충돌을 보류하며, 명시적 정정 링크와 계약 식별 근거로 관계를 확인한다.
- 반복 정정의 직전 변화와 검증된 관계 사슬을 통한 최초 기준 누적 변화를 분리한다.
- 분모 기준이 확인된 경우에만 `Decimal`로 매출액 대비 비율을 재계산하고 기재 비율과 분리한다.
- 크기 제한, ZIP 경로 이탈/엔트리/압축 해제 총량/압축비, XML DTD·엔티티 차단을 구현했다.
- `python -m disclosure_impact_agent <이전 HTML> <정정 HTML>` 오프라인 JSON 검증 명령을 추가했다.

### 실제 검증

- synthetic 원문 HTML을 읽는 파싱·비교 및 보안 테스트를 포함해 27개 테스트가 통과했다(0 실패, 기존 의존성 deprecation 경고 2개).
- 120억원과 12,000,000,000원 동등성, 120억원→90억원, 15%→서버 계산 11.25%, 종료일 변경을 확인했다.
- 표기만 변경, 통화/부가세/분모 기준 불일치, 미공개 상대방, 다른 계약, 반복 정정, 정정표 충돌, 문서 없음, 미지원 표를 검증했다.
- 모든 구조화 필드와 정정 항목의 증거 ID가 보존 문서 해시와 실제 블록에 존재함을 검증했다.
- CLI 결과는 `data_class=synthetic`, `llm_used=false`이며 두 문서 모두 증거 무결성 오류 0건이었다.

### 미검증

- 실제 DART 원문은 여전히 0건이며 API·실제 양식·ZIP 내부 구조는 검증하지 않았다.
- LLM은 사용하지 않았고 메모 주장 추출/영향 분류 성능은 미검증이다.
- 현재 지원 표 구조는 synthetic fixture 전용 확인이며 실제 DART 양식 지원을 주장하지 않는다.

### 다음 단계 준비

근거가 연결된 필드 변경과 명시적 보류 결과를 2단계 ClaimExtractor/ImpactAnalyzer 입력으로 사용할 수 있다. 실제 자료 일반화는 DART 키 또는 사용자가 제공하는 원문이 필요하다.
